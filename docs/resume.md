> 单卡 24G，总成本 ≈ ¥25，全流程可复现。

---

## 1. 一句话版本

在一个 66,581 段的维基语料上，训练 1.7B 小模型自主调用检索工具完成多跳问答：
用 DeepSeek 蒸馏 1,937 条带工具调用的轨迹做 SFT，把 EM 从 0.140 提到 0.405；
随后实现 GRPO 与 RFT 两种后训练方案，并给出“为何没有进一步提升”的量化归因。

## 2. 简历 bullet（4 条，按重要性排）

- **多跳检索 Agent 后训练**（Qwen3-1.7B + LoRA，单卡 24G，总成本 <¥30）
  独立搭建「数据构造 → SFT → RL → 评测」全链路：自建 BM25 检索环境与 `<tool_call>` 文本协议，
  在 HotpotQA 子集（200 题）上把 EM 从 **0.140 提升到 0.405（+26.5 点）**，`<answer>` 合规率 0.745 → 0.960。

- **数据构造**：用 DeepSeek-V4.1-Flash 按真实工具环境生成 4,200 条轨迹，设计“回放校验 + 答案匹配 + 难度分层”
  三级过滤，保留 1,937 条（两跳 74% / 格式 16% / 弃答 10%），平均工具调用 2.06 轮；
  训练集与评测集 qid 零重叠。

- **强化学习**：实现 Dr.GRPO（truncation masking + 组内归一化）与拒绝采样微调（RFT）两种方案；
  定位并修复三个工程问题（工具结果超出 completion 预算、截断样本污染梯度、std 归一化难度偏置），
  最终 GRPO 稳定收敛于 **EM 0.405 / F1 0.536**，RFT 于 **0.395 / F1 0.525**，均与 SFT 持平。

- **评测体系**：自建 200 题评测 + 5 类 bad case 归因 +「检索 × 正确」2×2 分解，
  量化出瓶颈从“协议遵循”（tag_rate 0.20 → 0.96）转移到“检索到了但答不对”（hit_wrong 157 → 111）。

## 4. 面试 Q&A

### Q1 这个项目解决了什么问题？
小模型（1.7B）不会用检索工具：不搜就编、搜一次就停、不按格式交付。
我把它训练成“会搜、会二次搜、会按协议作答”的 agent，并量化每一步的收益与瓶颈。

### Q2 为什么不用现成的 Search-R1 / ReTool？
它们的默认配置面向 8 卡 A100（7B/32B），我只有单卡 24G 和 ¥100 预算。
我复用了它们的方法论（SFT 冷启动 + 可验证奖励 + GRPO），但把模型缩到 1.7B、数据换成自建。

### Q3 SFT 数据怎么来的？
三条来源：
1. **格式样本**（16%）：comparison 题，教 `<tool_call>` 与 `<answer>` 协议；
2. **两跳样本**（74%）：bridge 题，50% 用 oracle 指定第一跳标题，让教师只学“第二跳怎么问”；
3. **弃答样本**（10%）：假实体，教“找不到就说 unknown”。

生成时用**真实的 BM25 环境**执行工具，而不是让模型编造检索结果——否则训练分布和推理分布不一致。

### Q4 数据怎么过滤？
三级：
1. 回放校验：重新执行工具调用，observation 必须逐字一致（挡掉环境漂移）；
2. 答案匹配：EM 之外允许 F1≥0.8 和“包含 gold 且不啰嗦”，避免误杀别名答案；
3. 难度/比例控制：弃答样本封顶 10%，两跳样本要求 ≥2 次调用。

### Q5 为什么用 LoRA 而不是全参？
1.7B 全参 Adam 需要 ~20GB 优化器状态 + 激活，24G 卡会 OOM；
而且任务是“学行为”（格式、检索节奏），不是注入新知识，LoRA r=32 足够。
全参在 1,841 条数据上也容易灾难性遗忘。

### Q6 SFT 前后发生了什么变化？
- EM 0.140 → **0.405**
- `<answer>` 合规率 0.745 → **0.960**
- 平均调用 1.62 → **2.21**（学会了第二跳）
- 无答案率 0.255 → **0.040**

### Q7 你怎么保证没有数据泄漏？
训练/验证/评测按 qid 切分，训练前断言 `train ∩ eval200 = 0`、`val ∩ eval200 = 0`。
另外评测题从未出现在生成池里（生成脚本按 split 文件排除）。

### Q8 GRPO 为什么没涨？
先说我修了什么：
1. 工具返回内容也算进 `max_completion_length`，256 装不下 → 提到 2048；
2. 37.5% 的 completion 被截断，污染梯度 → 开 `mask_truncated_completions`；
3. 除 std 有难度偏置 → 换 `Dr.GRPO` loss。

修完 reward 从 0.416 涨到 0.462，但评测 EM 与 SFT 相同。归因：
- 单卡 batch 只有 16，组内方差估计噪声大；
- 轨迹级奖励没有 step-level 信用分配；
- 1.7B 的容量在这个任务上已接近上限。

### Q9 RFT 为什么也没涨？
RFT 用的是自己采样的 592 条正确轨迹，但只来自 ~200 道题（同题多分支），
新信息有限；再混入全量 SFT 后，模型基本没变化（EM 0.395，噪声内）。
这说明**拒绝采样的收益取决于采样多样性**，而不是采样数量。

### Q10 200 题评测可信吗？
单次 200 题的 95% CI 约 **±7 个点**，所以 1–2 点的差异不能宣称提升。
正确做法是配对检验（McNemar）或 bootstrap；报告里我会写明 CI，而不是只报点估计。

### Q11 为什么 avg_calls 从 0.95 涨到 2.21 是好事？
eval200 里 160/200 是 bridge 题，必须两次检索。
基线几乎不搜第二次（0.95），结构上不可能做对；SFT 后 2.21 轮说明它学会了第二跳。

### Q12 检索器为什么用 BM25？
1. 零成本、可复现、无外部依赖；
2. 词面匹配的失败模式（同义改写、实体别名）正好是 bad case 的来源，便于分析；
3. 两跳检索的天然上限（AllHit@5=0.44）本身就是“为什么需要 agent”的论据。

### Q13 如果给你 8 张卡，你会怎么改？
- batch 从 16 提到 256，让 GRPO 的组内估计稳定；
- 换 7B 模型，验证容量是否是瓶颈；
- 加 step-level 奖励（每轮检索是否命中 gold 段落）；
- 用 vLLM 做异步 rollout，把 40 步压到 10 分钟。

### Q14 这个项目最大的坑是什么？
不是模型，是**工具协议与训练框架的不兼容**。
TRL 把工具调用解析成结构化 `tool_calls`，而我的 SFT 数据是纯文本协议，
导致模型第二轮输出半截 JSON、奖励恒为 0。最后靠打印原始 completion 才定位到。

### Q15 成本怎么控制的？
- 数据：DeepSeek Flash 空闲时段 + 缓存命中，4,200 条 ≈ ¥5.5；
- 训练：LoRA + 3090/4090 按量计费，SFT 28 分钟 ≈ ¥1.2；
- 评测：200 题 8 分钟 ≈ ¥0.5；
- 总成本 ≈ ¥25，其中 GPU ≈ ¥18。

## 5. 不要说的话

- ❌ “我预训练了一个 1.7B 模型” → 权重是官方的，你做的是后训练
- ❌ “SOTA / 超过 Search-R1” → 你的语料和评测都是子集，只能做相对比较
- ❌ “GRPO 提升了效果” → 数据是持平，如实说持平反而加分
- ❌ “200 题上提升了 2 个点” → 在 CI 之内，不能宣称显著
